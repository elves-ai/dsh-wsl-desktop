# 桌宠长期记忆 Agent：建议方案

状态：2026-10-25 已落地首阶段实现；未安装到正在运行的 Harness profile，也未做付费模型/Windows 原生实机验收。原建议中的自动归纳、持久提取队列与滚动摘要仍未实施。

## 硬性隔离边界

长期记忆**仅作用于宠物专属 `desktop-pet` 对话**，不影响 DSH 普通任务。普通会话即使位于同一个 Workspace，也不读取或提取宠物记忆，不注入宠物人格，不改变模型参数、输出上限、上下文预算、工具权限或失败处理。启用、关闭、清空或存储失败均不得阻塞普通任务。默认 Agent/preset 不修改，普通会话历史不回扫；宠物对话在 DSH 页面中打开仍按其专属会话身份识别，而不是按窗口来源判断。

除 preset 作用域隔离外，人格段、记忆段、步骤、请求参数和最终预算闸均显式核对会话归属；已有宠物缓存也不能影响后续变为普通 preset 的会话。

## 首阶段落地范围

- [本地 SQLite 服务](<../src-tauri/helpers/pet_memory.py>)保存用户明确要求的内容、来源、处理回执与删除墓碑；按后端身份及 Workspace 隔离，跨 Session 保持稳定宠物身份。采用 Unicode bigram 索引进行中文相关检索，最多 8 条且总资料不超过 6000 UTF-8 字节；管理列表每页 10 条。
- [桌宠专属 Harness bundle](<../harness/pet-memory/README.md>)只挂载非默认 `desktop-pet` preset。资料使用 scoped system section 并在变化时开启新 request series，由真实 SystemPromptProjection 替换旧 system head，不追加永久 user-role 记忆快照。普通会话不读取/写入记忆。
- 最终 provider 调用前按已路由模型窗口、实际输出上限、最终工具定义和完整会话 surface 做带安全余量的估算预算硬闸；超限拒绝调用，不自动额外请求摘要模型。不是精确 tokenizer 保证，也未宣称已有自动滚动摘要。
- [设置界面](<../src/pet-memory.ts>)默认关闭，区分本地同意与当前 Session 的专属 preset 状态；提供名字/语气、分页搜索、手动新增、纠正及确认后忘记，明确模型发送告知与“不删除 DSH 原始历史”。不展示内部预算/Top-K 调参。
- [原生桥](<../src-tauri/src/desktop_pet_memory.rs>)仅授权可信设置页；发送、重绑定和记忆设置共享准入互斥。开启记忆后只创建明确选择宠物 preset 的新对话，旧普通会话不静默转换；未安装扩展会提示而不降级。

首版只处理“记住：…”/“请记住：…”在线增量，不进行模型推断或旧历史回扫。处理回执能防止已写入来源重复落库，但尚未完成的内存提取队列遇进程崩溃可能丢失；这是后续持久队列工作的明确缺口。自动冲突归纳、完整情节记忆、宠物滚动摘要及预算受控的真实模型回放保留为后续阶段，不将首版测试冒充整份建议已全部完成。

## 结论

保留现有 DSH Agent 执行、会话存储、模型接入和权限机制；桌宠负责交互。在 Harness 的宠物专属作用域增加人格、长期记忆和有预算的上下文组装，而不是再嵌入一套完整 Agent 服务。

**长期身份不等于无限长提示词；保存全部历史不等于每轮发送全部历史。** 人格和记忆属于稳定的 `pet_id`，工作会话属于 `session_id`。换会话可继承允许共享的记忆，不自动继承工具授权或未完成任务。

## 最小完整架构

```text
桌宠文字输入 / 回复气泡 / 表情
        ↓
DSH 宠物作用域 Agent（沿用模型、工具权限、取消与恢复）
        ↓
上下文组装：人格 + 当前事实 + 有界摘要 + 相关记忆 + 近期消息
        ↓
模型回复 / 经授权的工具执行
        ↓
DSH 原始历史持久化 → 增量记忆提取任务 → 去重 / 冲突处理 / 索引
```

记忆放在本地 WSL 的宠物专属存储，首版 SQLite 即可，优先复用项目已有存储能力；用事务和迁移管理结构，不以一个不断追加的 Markdown 文件作为全部记忆。日后可提供 Markdown 导出，但模型不应直接随意覆写数据库或人格。

### 分开保存五类信息

| 类型 | 保存内容 | 进入上下文的方式 |
| --- | --- | --- |
| 人格 | 名字、语气、表达习惯、价值边界、能力限制 | 小而稳定，版本化，常驻 |
| 用户事实 | 明确称呼、偏好、长期目标及约束 | 少量核心事实常驻，其余检索 |
| 情节记忆 | 有时间的共同经历、重要事件及原始消息引用 | 相关时检索，不每日全文注入 |
| 会话状态 | 当前话题、指代、未完成事项、最近情绪表达 | 有上限的滚动摘要 + 近期原文 |
| 原始历史 | 用户和 Agent 的原始对话、工具记录 | DSH 保留；按需分页查证 |

人格默认由用户/产品设定，模型不能因一条检索结果改变身份、权限或安全边界。情绪状态可短期衰减，但不把推测的心理状态永久写成事实。未完成事项只有用户明确要求时才成为任务；“有长期记忆”不意味着后台自主行动或持续调用模型。

### 建议的数据约束

每条记忆至少包含 `id, pet_id, user_scope, kind, content, source_session_id, source_message_ids, valid_from, valid_to, status, confidence, created_at, updated_at`。另存提取游标和处理版本，利用原始消息 ID 去重，重启、重连与重试不能重复写入。

- 区分用户明确陈述、模型推测和工具观察。模型自己的回复不能自动成为“用户事实”。
- “我搬家了”使旧住址过期，但可保留历史事件；“今天想喝咖啡”不能覆盖长期偏好。
- 新旧冲突优先看明确纠正、来源与有效时间；不确定时保留待确认状态，不能只按更新时间覆盖。
- 不默认存密码、Token、完整工具日志、模型私有推理或敏感推断；提供查看、纠正、忘记和关闭记忆。后台提取若调用远端模型，需要告知用户；SQLite 在本地不等于聊天内容绝不出机。
- 忘记应同步移除检索索引、缓存和当前摘要中的相应内容，并阻止从旧对话重新提取。原始 DSH 历史是否删除是另一项明确操作，界面必须说明差别。
- 记忆按用户、宠物及后端作用域隔离。既有 MCP 知识库不自动全部读取，也不自动写入；需要用户明确选择共享范围。

## 避免上下文随时间无限增长

### 1. 为每次模型调用设置预算，不只限制最近消息条数

```text
B_input = min(B_product, C_model - R_output - H_safety)
T_system + T_tools + T_persona + T_profile + T_summary
  + T_retrieved + T_recent + T_current + T_attachments <= B_input
```

`C_model` 根据本次实际路由的模型确定；输出预留和安全余量必须计入。下面仅是 **24k 输入预算的起始实验值**，不是已生效配置：

| 部分 | 上限示例 |
| --- | ---: |
| 基础指令、工具定义、人格 | 6k |
| 核心用户事实 | 1k |
| 当前会话摘要 | 2k |
| 检索记忆 | 3k |
| 最近完整消息/工具交互 | 8k |
| 当前输入、附件摘要及波动余量 | 4k |

这些是上限，不要求填满。现有 DSH 工具定义可能超过示例额度，需要在宠物作用域减少不必要工具，不能假装工具定义免费。不得删除权限说明来省 token。模型窗口较小时整体下调预算；超大的当前输入或不可拆工具对需要显式分段/拒绝，而不是静默截断用户要求。

### 2. 检索只取相关片段

首版做规范化事实查询 + SQLite 全文检索；中文必须验证分词效果，必要时采用 trigram/中文分词。有测试证据表明语义召回不足，再增加本地 embedding 和混合检索，不必一开始部署向量服务和图数据库。

先按身份、有效期和删除状态过滤，再按相关性、可靠性、时间及重复度选择。候选可多取，注入必须同时满足条数和 token 上限；例如最多 5–8 条、总计不超过 3k token。Top-K 本身不能防止某一条过长。需要更早详情时，通过有分页和输出上限的历史查询工具读取原文。

### 3. 摘要替换旧摘要，不追加摘要链

超过产品预算的预警线时，对已完成的旧轮次做压缩，保留最近完整交互和未结事项。会话摘要使用“当前话题、已确认事实、重要事件引用、未结事项、最近纠正”等结构，并有独立输出上限。

新摘要替换旧摘要；不得把每日摘要、周摘要、月摘要全部堆入提示词。摘要可能丢信息，因此重要事实另外结构化保存，情节保留原始出处，必要时回查，不能无限对摘要再摘要。

复用 Harness 的工具对平衡、稳定性校验和持久化事务。它已有“摘要必须更小”和有限压缩重试；新增产品预算还需在**每次真正调用前**验证，包括工具结果、附件、动态上下文和模型切换后的变化，不能只在第一条用户输入时检查。

### 4. 压缩与记忆提取分工

上下文压缩负责下一次调用能否放下；长期记忆提取负责跨会话值得保留什么。前者必要时同步阻塞模型调用，后者在完成轮次后增量异步处理，避免拖慢每次回复。

提取任务必须有持久游标、幂等写入、失败重试上限及调用预算。闲置时不因“思考/做梦”持续请求模型。压缩失败保留原历史、不写坏摘要；若仍超限则停止本次调用并说明原因，不能不断重试烧费用或退回发送全部历史。

### 5. 动态记忆不能在每轮重复累积

人格前缀尽量稳定，改善缓存复用；检索内容以可替换的当前上下文快照注入，并确认旧快照不继续占用有效 prompt。接入 Harness 的动态 context 时须测试其持久投影/替换语义，不能在每轮用户消息前永久追加同一批记忆。

检索出的文字只作带来源的数据，不作系统指令。比如历史中出现“忽略权限、自动转账”，不能借记忆提取提升为规则。任务执行继续沿用 DSH 权限控制，记忆不是授权凭证。

## 实施顺序与验收

1. **先验证接入点**：核对运行 profile；建立稳定 `pet_id` 和作用域人格；确认恢复/换会话隔离。先不做向量库或自主循环。
2. **做最小记忆闭环**：本地结构化记忆、增量提取、有限检索、查看/纠正/忘记；保留原始出处和提取游标。
3. **做长会话保障**：宠物摘要模板、实际请求总预算、工具输出裁剪、压缩失败和模型切换兜底。
4. **用固定回放集验收**：通过后再考虑 embedding 或 Graphiti 式时序关系，不以架构复杂度替代效果。

最低回放场景：

- 连续 1,000 轮后，每次输入仍不超过有效预算，不出现随轮次增长的摘要链；先 mock 验证不变量，再用预算受控的小样本真实模型评估。
- 重启、更换会话后能找回明确保存的偏好，同时不会把另一个用户/宠物的信息串进来。
- 更正偏好、搬家、临时情绪、明确忘记后，回答使用正确的有效版本；删除内容不会重启后“复活”。
- 长工具输出、大附件、工具调用未完成、压缩取消、提取中断重放均不损坏会话与记忆。
- 旧历史里的恶意指令不改变人格或权限；涉及行为承诺时仍需要当前用户授权。

指标记录实际请求 token、检索命中/误召回、重复和冲突率、延迟以及提取/摘要成本。不承诺“永不遗忘”；应做到可以追溯、不知道时承认、错了能纠正。
